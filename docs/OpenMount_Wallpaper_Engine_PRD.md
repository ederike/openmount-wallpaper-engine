## 1. 文档概述

### 1.1 目的

本产品需求文档（PRD）定义了开源壁纸引擎 **OpenMount Wallpaper Engine (OMWE)** 的完整功能需求、交互逻辑、技术边界与非功能需求。该产品旨在提供一种基于“映射挂载（Mount Mapping）”的精确内容控制壁纸播放系统，区别于传统壁纸引擎仅支持简单文件或视频指定的方式。

### 1.2 产品愿景

打造一个高性能、跨平台、开源的壁纸引擎，以类文件管理器的主操控界面为核心，通过虚拟映射挂载实现对本地图片与视频资源的精细选择与播放控制。支持传统顺序播放与创新的“卷轴模式（Scroll Mode）”，并保证在 Windows 与 macOS 的 x86 与 ARM 架构上均能流畅运行。

### 1.3 目标用户

- 希望精细控制桌面壁纸内容范围的高级用户
- 需要将多个文件夹/子文件夹内容按自定义顺序与选择策略组合播放的创作者
- 偏好开源、可定制、无强制云同步的桌面美化工具用户
- 同时使用 Windows 与 macOS 的跨平台用户

## 2. 范围定义

### 2.1 范围内（In Scope）

- 虚拟映射挂载系统（文件与文件夹）
- 类文件管理器主操控界面
- 选择框驱动的播放内容控制
- 持续内容检测与刷新同步
- 传统播放模式与卷轴模式
- 完整的快捷键系统
- Windows 与 macOS 原生壁纸设置能力
- 开源发布（许可证：GPL-3.0-or-later）

### 2.2 范围外（Out of Scope，v1.0）

- 在线壁纸商店与社区分享
- 云同步与账号系统
- 实时网页壁纸 / HTML 壁纸
- 音频播放与可视化
- 多显示器独立配置（v1.0 仅支持主显示器，后续可扩展）
- 移动端或 Linux 版本

## 3. 核心概念定义

| 术语 | 定义 |
|------|------|
| **映射挂载（Mount）** | 在 OMWE 内部创建的对原始文件/文件夹路径的引用记录，不复制文件内容，仅记录路径与元数据 |
| **挂载树（Mount Tree）** | OMWE 主界面中呈现的虚拟文件夹结构，可独立于原始文件系统进行组织 |
| **选择状态（Selection State）** | 每个挂载节点上的布尔值，决定该节点及其内容是否参与播放 |
| **持续内容检测（Continuous Detection）** | 针对某个挂载文件夹开启的开关，刷新时自动同步原始文件夹的新增/删除内容 |
| **播放池（Playback Pool）** | 当前所有被选中的可播放资源集合，播放引擎从中选取内容 |
| **卷轴（Scroll Canvas）** | 卷轴模式下将所有选中内容按等高规则水平拼接形成的虚拟长画布 |

## 4. 功能需求

### 4.1 主操控界面（Main Control Interface）

主界面采用类文件管理器布局，支持树状/列表/缩略图三种视图切换。

#### 4.1.1 界面组成

- 左侧导航树（挂载树）
- 主区域：当前路径下的文件与文件夹预览（仅显示可加载的图片与视频）
- 顶部工具栏：挂载、刷新、排序、视图切换、播放控制入口
- 右侧或底部属性面板：显示当前选中项的原始路径、选择状态、检测设置等
- 状态栏：显示当前播放池数量、检测状态、壁纸运行状态

#### 4.1.2 可见性规则

- 仅显示支持的图片格式（jpg、jpeg、png、webp、bmp、gif、tiff）与视频格式（mp4、mkv、mov、webm、avi）
- 文本、文档、压缩包、可执行文件等不可播放内容不显示在主界面
- 文件夹始终显示（即使内部暂无可播放内容）

#### 4.1.3 选择框逻辑

- 每个文件与文件夹节点均有独立选择框
- **文件夹选择框勾选**：递归选中该文件夹及其所有子文件夹下的全部可播放文件
- **取消勾选**：递归取消选中
- 子项选择状态变化不影响父文件夹选择框的视觉状态（父文件夹选择框表示“是否全选意图”，实际播放以叶子节点选择状态为准）
- 选择状态仅影响播放池，不影响挂载本身的存在

#### 4.1.4 文件管理器通用功能

- 排序：名称、修改时间、大小、类型、自定义顺序（支持拖拽重排）
- 筛选：按类型、选择状态、检测状态
- 搜索：在当前挂载树内搜索文件名
- 拖拽排序：在同一父节点内可自由拖拽调整顺序（该顺序仅影响 OMWE 内部播放顺序，不影响原始文件系统）
- 重命名挂载节点：仅修改 OMWE 内显示名称，不影响原始文件

### 4.2 挂载系统（Mounting System）

#### 4.2.1 挂载方式

- 支持挂载单个文件或整个文件夹
- 可在根目录挂载，也可在任意已存在的挂载文件夹节点下挂载新内容
- 挂载操作仅在 OMWE 内部创建映射记录，**不对原始文件系统进行任何移动、复制或修改**

#### 4.2.2 重复挂载规则

- **不进行去重**：允许同一原始文件被多次挂载到不同位置
- 示例：已挂载 `a/11.png` 后，仍可在根目录再次挂载 `11.png`，二者视为完全独立的挂载节点
- 每个挂载节点独立维护自己的选择状态、排序位置与检测设置
- 播放时，同一原始文件若被多个被选中的挂载节点引用，则按各自节点规则分别计入播放池（可能被多次播放）

#### 4.2.3 持续内容检测

- 每个挂载文件夹节点拥有独立的“持续内容检测”开关
- **设置继承规则**：父文件夹开启后，其所有子文件夹自动同步开启（可手动在子文件夹单独关闭，但刷新时会重新同步父级设置，除非用户明确锁定子级）
- 点击“刷新”时：
  - 对已开启检测的文件夹：扫描原始路径，自动为新增的可播放文件创建挂载节点，自动移除原始路径中已不存在的挂载节点
  - 对未开启检测的文件夹：仅标记失效（原始文件不存在时文件名标红），不自动删除挂载节点
- 失效挂载节点：文件名标红，不参与播放，跳过处理
- 刷新范围：仅对当前选中的文件夹及其子树生效，或提供“刷新全部”选项

#### 4.2.4 删除规则

- 默认删除行为：仅删除 OMWE 内的挂载记录（映射）
- 提供独立选项“同时删除原始文件”（默认关闭，需二次确认）
- 删除文件夹挂载时，递归删除其所有子挂载节点（映射层面）

#### 4.2.5 边界条件补充规则

| 场景 | 处理规则 |
|------|----------|
| 原始文件被外部删除 | 未开启检测：标红失效；开启检测：刷新后自动移除挂载 |
| 原始文件被外部移动 | 视为路径失效，标红；提供“重新定位”功能 |
| 原始文件夹权限变化 | 检测失败时提示权限错误，保留现有挂载 |
| 符号链接 / 快捷方式 | 解析到真实路径后挂载，记录解析后路径 |
| 挂载路径包含特殊字符 | 正常支持，内部使用 UTF-8 路径存储 |
| 同一文件夹多次挂载到不同位置 | 各自独立，互不影响检测与选择 |
| 挂载循环引用 | 禁止（检测时阻止将父级挂载到子级下） |

### 4.3 播放系统

#### 4.3.1 播放池构建

- 播放池由所有选择状态为“选中”且原始文件存在且格式支持的挂载节点组成
- 同一原始文件若被多个选中节点引用，按节点独立计入（可重复出现）
- 播放池顺序遵循挂载树中的自定义排序（拖拽顺序优先，其次按名称排序）

#### 4.3.2 传统模式（Traditional Mode）

支持以下播放策略：

- 名称正序
- 名称逆序
- 文件夹内自定义顺序
- 随机播放（可设置是否避免连续重复）
- 单张停留时间可调（图片）
- 视频播放完毕自动切换或循环当前视频（可配置）
- 淡入淡出过渡效果（可开关、可调时长）
- 填充模式：填充、适应、拉伸、平铺、居中
- 背景色设置（当内容未铺满时）

#### 4.3.3 卷轴模式（Scroll Mode）

**核心逻辑**：

1. 将播放池中所有内容等比缩放，使高度等于当前显示器高度
2. 水平方向按自定义顺序依次排列，图片/视频之间保留可配置的微小间隙（默认 2px）
3. 形成一张虚拟长卷轴
4. 按设定方向（左→右 或 右→左）匀速滚动
5. 视频行为：当视频左边缘进入屏幕可视区域时开始播放，当视频右边缘完全离开屏幕时停止播放并释放资源

**可配置项**：

- 滚动方向
- 速度：预设 10 档 + 自定义数值（单位：像素/秒）
- 暂停 / 继续
- 整体透明度
- 间隙大小
- 是否循环滚动
- 视频预加载策略（提前 N 秒加载）

#### 4.3.4 通用播放控制

- 开始 / 暂停壁纸
- 下一张 / 上一张（传统模式）
- 重置卷轴位置（卷轴模式）
- 实时预览当前播放内容
- 系统托盘图标控制

### 4.4 快捷键系统

- 所有关键操作均支持快捷键绑定
- 提供默认快捷键方案
- 用户可自由修改、冲突检测
- 支持全局快捷键（即使 OMWE 窗口未聚焦）
- 快捷键配置持久化存储

建议默认快捷键示例：

- `Ctrl/Cmd + Shift + W`：显示/隐藏主界面
- `Ctrl/Cmd + P`：暂停/继续播放
- `Ctrl/Cmd + Right`：下一张
- `Ctrl/Cmd + [` / `]`：调整卷轴速度

### 4.5 设置与持久化

- 所有挂载树结构、选择状态、排序、检测开关、播放设置均本地持久化（推荐 SQLite 或 JSON + 二进制索引）
- 支持导出/导入配置包
- 壁纸运行状态独立于主界面（关闭主界面后壁纸继续运行）

## 5. 非功能需求

### 5.1 性能

- 主界面加载 10,000+ 挂载节点时保持流畅（虚拟列表）
- 视频播放与卷轴滚动在 4K 分辨率下保持 ≥ 60 FPS
- 内存占用：空闲时 < 150 MB，播放高分辨率视频时合理增长
- 启动时间：冷启动 < 3 秒

### 5.2 兼容性

- Windows 10 21H2+ / Windows 11
- macOS 12 Monterey 及以上
- 架构：x86_64 与 ARM64 均需提供官方构建
- 高 DPI 与多缩放比例支持
- 深色/浅色主题跟随系统

### 5.3 可靠性

- 原始文件被外部删除或移动时不应导致崩溃
- 异常退出后可恢复上次挂载状态
- 提供日志系统便于问题排查

### 5.4 安全性

- 不主动扫描或上传用户文件内容
- 删除原始文件操作需明确二次确认
- 开源透明

## 6. 技术架构建议

### 6.1 推荐技术栈

| 层级 | 推荐方案 | 理由 |
|------|----------|------|
| 核心语言 | **Rust** | 内存安全、高性能、优秀的跨平台编译支持、适合处理大量文件路径与并发检测 |
| UI 框架 | Tauri 2.x + React/Vue 或 egui | Tauri 轻量且可调用系统 API；egui 更适合纯原生高性能界面 |
| 视频解码 | ffmpeg-next 或 gstreamer | 成熟的跨平台视频处理 |
| 图形渲染 | wgpu 或 OpenGL | 保证卷轴模式流畅滚动 |
| 数据存储 | SQLite (rusqlite) | 结构化存储挂载树与配置 |
| 壁纸设置 | 平台原生 API（Windows: IDesktopWallpaper / 自定义层；macOS: NSWorkspace / 桌面窗口） | 可靠设置动态壁纸 |

### 6.2 构建与分发

- 使用 GitHub Actions 进行 CI/CD
- 提供以下构建产物：
  - Windows: `.msi` 或 `.exe`（x86_64 / ARM64）
  - macOS: `.dmg` 或 `.pkg`（Universal Binary 优先，或分架构）
- 支持通过包管理器安装（可选：winget、Homebrew）

### 6.3 开源策略

- 仓库结构清晰，包含详细 README、贡献指南与架构文档
- 提供开发者文档说明挂载系统与播放引擎的扩展点

## 7. 用户故事示例

1. **作为用户**，我希望将某个照片文件夹挂载到根目录，并只勾选其中部分子文件夹，以便精确控制哪些照片会出现在壁纸中。
2. **作为用户**，我希望对某个挂载文件夹开启持续检测，这样当我向原始文件夹添加新图片后，点击刷新即可自动出现在 OMWE 中。
3. **作为用户**，我希望同一张图片可以同时挂载在多个位置并独立控制选择状态，以便在不同上下文中复用。
4. **作为用户**，我希望在卷轴模式下将所有精选图片与视频等高拼接后缓慢滚动，营造沉浸式桌面体验。
5. **作为用户**，我希望删除挂载时默认不删除原始文件，避免误操作。

## 8. 验收标准（Acceptance Criteria）

- [ ] 可成功挂载单个文件与整个文件夹，并在主界面正确显示可播放内容
- [ ] 选择框逻辑符合递归选择规则，播放池仅包含选中内容
- [ ] 同一原始文件可多次挂载且互不影响
- [ ] 持续内容检测可正确识别新增与删除，并按规则处理
- [ ] 传统模式支持所有规定的播放顺序与过渡效果
- [ ] 卷轴模式可正确等比缩放、水平拼接并流畅滚动，视频进出屏幕时正确启停
- [ ] 所有设置支持快捷键自定义
- [ ] 在 Windows 与 macOS 的 x86_64 与 ARM64 上均可正常设置壁纸
- [ ] 删除操作默认仅移除映射，原始文件安全
